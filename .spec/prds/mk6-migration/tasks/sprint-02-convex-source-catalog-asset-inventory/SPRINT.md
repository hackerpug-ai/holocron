# Sprint 2: Convex Source Catalog and Asset Inventory

**Sequence:** 2
**Timeline:** Phase 0 — Leading INFRA
**Status:** In Progress

---

## Overview

This is the second leading-INFRA sprint: it produces the **machine-readable migration-contract artifact** (`12-convex-source-catalog.yaml`) that every later DATA/SVC/SYNC sprint reads as the authority for what moves where. Against a real `convex export`, it proves that all 60 legacy Convex tables — plus every field and every storage reference — carry one approved disposition (`preserve` / `merge` / `drop` / `regenerate` / `archive`) with a target relation, a computable expected-target-count formula, an owner, and an approval. No source surface may be silently dropped; every intentional loss is a versioned approval.

The sprint stands up the `holo catalog:*` operator surface: a coverage/verify build-gate that fails closed on any unmapped table or field, a reconciliation-report + asset-inventory generator (legacy-ID, SHA-256, byte-length, MIME, content-addressed target, disposition per retained object), and the merge-collapse proof (business 12→3 `analysis_*`, research 5→3 `research_*` — no per-domain shells in the targets). This catalog is the contract Sprint 04's schema is validated against and Sprint 14's ETL must reconcile to zero unexplained variance.

---

## Human Test Deliverable

An operator can prove — against a real `convex export` and the committed `12-convex-source-catalog.yaml` — that every one of the 60 legacy tables and every storage reference has an approved disposition with a computable expected-target formula, that the coverage gate fails closed the moment a surface goes unmapped, and that the retained-asset inventory carries integrity evidence per object.

**Test Steps:**
1. Run `holo catalog:verify` against a real `convex export` — reports 60/60 tables each with an approved disposition.
2. Run `holo catalog:coverage` — every field and storage reference maps to preserve/merge/drop/regenerate/archive with owner+approval.
3. Delete one table's entry and re-run `holo catalog:verify` — exits non-zero naming the unmapped table.
4. Run `holo catalog:reconcile --dry-run` — prints per-table expected-target count formulas and approved exceptions.
5. Run `holo catalog:assets` — lists every retained storage object with legacy-ID, SHA-256, byte-length, MIME, target, disposition.
6. Run `holo catalog:merges` — reports business 12→3 and research 5→3 collapses with no per-domain shells in the targets.
