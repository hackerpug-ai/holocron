# Data Schema

No new tables are proposed on the device. The web client reads the existing `documents`,
`conversations`, `chatMessages` and `researchSessions` tables through the BFF, and introduces
wire-level and client-level shapes of its own. The only genuinely new persistence is BetterAuth's
four-table identity schema, whose location is an open decision (see §Technical Risks).

## SharedDocument

**Proposed by** `nextjs-planner`. **Source:** Origin GET /article/:shareToken - but TODAY that route returns rendered HTML, not this shape. See api_endpoints: a JSON representation is a hard prerequisite for the Next reader.

**Properties**

- `title`
- `content (raw markdown)`
- `category`
- `date`
- `createdAt`
- `researchType`

**Notes.** Exactly the existing exported ArticleDoc type in services/platform/src/http/article.ts, already produced by selectPublicArticle(). The Server Component needs the markdown; it cannot and must not parse the origin's HTML back into an AST.

---

## DocumentAsset

**Proposed by** `nextjs-planner`. **Source:** Origin GET /article/:shareToken/assets/:fileObjectId, proxied by the new Route Handler.

**Properties**

- `fileObjectId`
- `contentHash`
- `mimeType`
- `bytes`

**Notes.** The origin join already enforces is_public correctly, so authorisation is not re-implemented at the edge. Only the URL shape and cache headers change.

---

## OgImageCandidate

**Proposed by** `nextjs-planner`. **Source:** Derived: first image node found while walking the parsed mdast of SharedDocument.content.

**Properties**

- `src (rewritten to /d/<token>/assets/<id>)`
- `alt`
- `width`
- `height`

**Notes.** Feeds generateMetadata's openGraph.images. Must be derived from the same parse the page uses (React cache() dedupe), not a second regex pass over the markdown.

---

## LibraryDocument

**Proposed by** `nextjs-planner`. **Source:** tRPC documents.list / documents.search against the origin's existing hybrid FTS+vector search.

**Properties**

- `id`
- `title`
- `snippet`
- `category`
- `researchType`
- `status`
- `isPublic`
- `shareToken`
- `publishedAt`
- `updatedAt`

**Notes.** isPublic and shareToken must be on the LIST payload, not only the detail payload - the staged persona finding requires 'what is public right now' to be answerable by scanning rows, and the audit journey filters on it.

---

## UIMessage

**Proposed by** `nextjs-planner`. **Source:** AI SDK shape, folded client-side by a reducer from parts yielded by the chat.stream generator.

**Properties**

- `id`
- `role`
- `parts[] (text | tool-call | tool-result | invalidate)`

**Notes.** The invalidate part carries {entity, id} only - never record contents. Cards render from trpc.documents.byId / trpc.research.byId keyed by record id, which is what makes duplicate cards structurally impossible.

---

## Session

**Proposed by** `nextjs-planner`. **Source:** BetterAuth, read server-side only.

**Properties**

- `userId`
- `expiresAt`

**Notes.** Never read anywhere under the (public) route group. A public response carrying Vary: Cookie or Set-Cookie would fragment the edge cache per-user and silently destroy the 60s SLA - asserted by test, see FR-NEXT-03.

---

## ChatStreamPart

**Proposed by** `trpc-planner`. **Source:** BFF wire type, defined once in server/trpc/schemas/chat.ts and inferred on the client via inferRouterOutputs.

**Properties**

- `type (discriminator)`
- `turn-start: conversationId, messageId, clientTurnId`
- `text-delta / reasoning-delta: id, delta`
- `tool-*: toolCallId, toolName, input | output | errorText`
- `record-ref: kind, id`
- `invalidate: kind, id?`
- `turn-finish: messageId, finishReason, usage?`
- `turn-error: code, message, retriable`

**Notes.** ENFORCES the load-bearing rule. record-ref carries an id and nothing else (placement); invalidate carries an id and nothing else (freshness). No variant carries a record body - a card's contents structurally cannot travel on the stream, so the duplicate-card defect has no channel to occur on. tool-* field names are chosen to map 1:1 onto AI Elements props (ToolHeader state = input-streaming | input-available | output-available | output-error).

---

## DocumentRow

**Proposed by** `trpc-planner`. **Source:** Device documents table via MCP hybrid_search / list_documents.

**Properties**

- `id`
- `title`
- `snippet`
- `score?`
- `category`
- `researchType`
- `status`
- `isPublic`
- `updatedAt`

**Notes.** Today's device SearchResultItemSchema is { _id, title, score, content } ONLY - it carries no category, researchType, status, isPublic or updatedAt. That makes the Library row unable to show the type chip or the share badge, which is exactly the J3 failure ('he cannot tell whether a result is the digest, the transcript, or the research output') and the J4/J5 failure ('share state is not reflected on the row'). Fixing it per-row with documents.byId would cost one tunnel round trip per result and is forbidden. See FR-BFF-11.

## UIMessage (client state)

**Proposed by** `trpc-planner`. **Source:** Client-only, produced by the reducer folding ChatStreamPart; hydrated on load from conversations.byId.

**Properties**

- `id`
- `role ('user'|'assistant')`
- `parts: Array<TextPart | ReasoningPart | ToolPart | RecordRefPart>`
- `createdAt`
- `status ('streaming'|'complete'|'error')`

**Notes.** AI SDK UIMessage shape kept deliberately so AI Elements render it natively without useChat. RecordRefPart is { type:'record-ref', kind, id } - deduped by (kind,id) at reduce time.

---

## TrpcContext

**Proposed by** `trpc-planner`. **Source:** createContext({ req, resHeaders }) in the fetch adapter.

**Properties**

- `session: { userId, sessionId } | null`
- `device: DeviceClient (bound)`
- `requestId: string`
- `signal: AbortSignal`

**Notes.** Holds a BOUND client, never raw credentials, so no procedure can accidentally serialize a key into a response. signal is the request signal, threaded into every device call so client abort reaches the device.

---

## DeviceError (BFF-internal)

**Proposed by** `trpc-planner`. **Source:** BFF error taxonomy produced by DeviceClient.

**Properties**

- `kind: 'unreachable'|'auth_failed'|'device_5xx'|'tool_error'|'cancelled'`
- `toolName?`
- `deviceCode?`
- `requestId`

**Notes.** Mapped to TRPCError codes at the procedure boundary: unreachable->TIMEOUT, auth_failed->INTERNAL_SERVER_ERROR (client-facing code DEVICE_AUTH_FAILED), device_5xx->BAD_GATEWAY, cancelled->CLIENT_CLOSED_REQUEST. Raw device bodies, data_plane/source diagnostics and Postgres text are stripped by errorFormatter and never reach the client.

---

## AgentTurnContext (in-memory only, not persisted)

**Proposed by** `aisdk-planner`. **Source:** Constructed per-request inside the tRPC procedure handler

**Properties**

- `conversationId`
- `mcpClient (live handle, closed at turn end)`
- `abortSignal`
- `slashCommand (parsed, nullable)`

**Notes.** Never persisted - this is the AI SDK loop's working state for exactly one turn. Persisted conversation/message history is owned by trpc/BFF, not this lens.

---

## ToolInvocationRecord

**Proposed by** `aisdk-planner`. **Source:** Derived from tool-input-*/tool-output-* stream parts as they arrive

**Properties**

- `toolCallId`
- `toolName`
- `input`
- `output | errorText`
- `durationMs`

**Notes.** Ephemeral, client-side, exists only to drive ToolHeader/ToolInput/ToolOutput rendering - not a durable entity. If a durable tool-call audit log is wanted later, that's a platform/mastra concern, out of this lens's scope.

---

## researchSession (referenced, not owned)

**Proposed by** `aisdk-planner`. **Source:** Device platform's existing researchSession entity, queried via trpc.research.byId

**Properties**

- `id`
- `status`
- `progress`

**Notes.** The AI SDK loop only ever WRITES the initial hand-off call and READS nothing - polling and rendering are entirely the query layer's job, per the data-flow rule.

---

## user

**Proposed by** `betterauth-planner`. **Source:** BetterAuth core schema, generated by `npx auth@latest generate`

**Properties**

- `id`
- `name`
- `email (unique)`
- `emailVerified`
- `image`
- `createdAt`
- `updatedAt`

**Notes.** Will contain exactly one row, forever. No additionalFields, no role, no org membership. If co-located in the device Postgres instead of D1, rename via user: { modelName: 'auth_user' } - user, session, account are dangerously generic names to claim in a 90-table public schema.

---

## session

**Proposed by** `betterauth-planner`. **Source:** BetterAuth core schema

**Properties**

- `id`
- `userId -> user.id`
- `token (unique)`
- `expiresAt`
- `ipAddress`
- `userAgent`
- `createdAt`
- `updatedAt`

**Notes.** Opaque server-side session tokens, not JWTs. Deleting a row is real revocation, subject only to the cookie-cache window. expiresIn 30 days, updateAge 1 day.

---

## account

**Proposed by** `betterauth-planner`. **Source:** BetterAuth core schema

**Properties**

- `id`
- `userId -> user.id`
- `accountId`
- `providerId ('credential')`
- `password (scrypt hash)`
- `createdAt`
- `updatedAt`

**Notes.** The password hash lives here, not on user. Only one row with providerId: 'credential'. No OAuth provider rows will ever exist.

---

## verification

**Proposed by** `betterauth-planner`. **Source:** BetterAuth core schema

**Properties**

- `id`
- `identifier`
- `value`
- `expiresAt`
- `createdAt`
- `updatedAt`

**Notes.** Created by the schema generator and left in place, but effectively unused: email verification and email password-reset are both off, so nothing writes here. Do not delete the table - BetterAuth's adapter expects it.

---

## Session cookie pair

**Proposed by** `betterauth-planner`. **Source:** Set by the BetterAuth handler on sign-in; cleared on sign-out

**Properties**

- `better-auth.session_token (opaque token, httpOnly, secure, sameSite=lax, host-only, path=/)`
- `better-auth.session_data (signed cookie cache payload, same flags)`

**Notes.** session_data is what makes ordinary navigation free - it is signature-verified with BETTER_AUTH_SECRET in the Worker with no store read. Explicitly do NOT enable crossSubDomainCookies: a .holocrnlib.com cookie would be sent to origin-docs.holocrnlib.com as well, handing the operator's session cookie to the device origin behind CF Access for no benefit.

---

## documents.is_public / documents.share_token

**Proposed by** `betterauth-planner`. **Source:** Existing device Postgres - services/platform/src/db/schema/documents.ts

**Properties**

- `is_public boolean default false`
- `share_token text`

**Notes.** The ENTIRE access-control model for the public surface. Verified in-repo. Not a BetterAuth entity and must never become one: the reader has no identity, so there is nothing to authorize against except the token and the flag.
