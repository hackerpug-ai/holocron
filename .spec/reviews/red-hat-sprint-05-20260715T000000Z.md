### MEDIUM-1: SPRINT.md Human Test Deliverable diverges from gate — Tailscale HTTPS vs localhost HTTP

**Severity**: MEDIUM | **Confidence**: HIGH (3 sources: mastra-reviewer, security-reviewer, skill pre-check)

**Evidence**:
- `SPRINT.md:36`: `curl https://mini/health` — claims HTTPS over Tailscale hostname
- `SPRINT.md:37-39`: `curl -X POST https://mini/api/missions/x/steer` — same HTTPS surface
- `gate-plan.json:11`: `curl http://127.0.0.1:4111/health` — tests HTTP over localhost
- Source search: `rg -n 'tailscale|https://mini|TLS|certificate|HOLO_TLS' services/platform/src/` → **ZERO matches**
- `index.ts:98-100`: `Bun.serve({ port, fetch: app.fetch })` — no `tls: {...}` option

**Impact**: The sprint's entire architectural framing is AP-7 "tailnet trust boundary," but the gate never proved the boundary over Tailscale/HTTPS. The auth middleware logic is identical regardless of transport, so the enforcement IS real — but the documented Human Test Deliverable describes a surface (Tailscale HTTPS via `mini` hostname) that was never tested and has no source implementation. An operator following SPRINT.md literally would find no `https://mini` endpoint listening.

**Fix**: Either (a) add a note to SPRINT.md that TLS termination is provided externally (Tailscale Serve) and the gate tests the HTTP boundary directly, or (b) add Tailscale Serve setup and test against the real HTTPS endpoint.

### MEDIUM-2: Queue probe is a process-local boolean flag, not a real queue health check

**Severity**: MEDIUM | **Confidence**: HIGH (2 sources: mastra-reviewer, skill pre-check)

**Evidence**: `services/platform/src/http/health.ts:19-33`
```typescript
export class ProcessLocalQueue {
  #started = false;
  start() { this.#started = true; }
  stop() { this.#started = false; }
  isReady(): boolean { return this.#started; }
}
```
`probeQueue()` calls `queue.isReady()` which returns `#started` — set to `true` at process start. This is process-liveness, not queue readiness. The `latency_ms` is a trivial `await Promise.resolve()` + `Math.max(1, ...)`.

**Impact**: AC-2 says "/health probes queue readiness" — a boolean flag cannot detect a dead graphile-worker, full queue table, or poisoned job. The code comments acknowledge this deferral to Sprint 11.

**Fix**: Replace `ProcessLocalQueue` with a real queue adapter probe when Sprint 11 lands. For now, the `/health` queue field should be understood as "process started" not "queue healthy."

### MEDIUM-3: Empty `agents: {}` / `workflows: {}` makes service-5 AC-3 vacuously satisfied

**Severity**: MEDIUM | **Confidence**: HIGH (2 sources: mastra-reviewer, skill pre-check)

**Evidence**: `services/platform/src/index.ts:68-69` — `agents: {}, workflows: {}`. The sole `agent.generate()` call site is `compat/cells/agent.ts:103` (Sprint 01 compat spike). service-5 AC-3 premise: "GIVEN agents and workflows are implemented with Mastra 1.x patterns" — zero production agents exist in the platform service.

**Impact**: The tripwire helpers (`assertNoTripwire`, `handleStreamChunk`, `assertNoTripwireInStream`) are well-implemented and wired at the one compat-spike call site, but there are zero production agent call sites to protect. When production agents are eventually registered, there is no lint gate or compilation constraint forcing tripwire handling at new call sites.

**Fix**: Add a lint/CI rule that files calling `.generate()`/`.stream()` must import `assertNoTripwire`/`assertNoTripwireInStream` before the first production agent is registered.
