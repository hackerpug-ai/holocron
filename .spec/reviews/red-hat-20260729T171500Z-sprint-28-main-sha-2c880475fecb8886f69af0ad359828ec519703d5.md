## Findings

### CRITICAL-1 — Caller `PATH` controls helpers before the credential-safe environment exists

`run_live_probe` builds its command with bare `env` at `scripts/prove-r2-readonly.sh:390-403` and invokes it at `:420`; mint does the same at `:199-201`. Bash resolves that `env` through caller `PATH` before `-i` has any effect. At that point the command line contains AWS access/secret/session values or a Cloudflare bearer token. The provider resolver also runs bare `python3` at `scripts/lib/r2-ro-live.sh:33-85`; a caller-controlled Python can emit an attacker path, which is subsequently executed with restore credentials.

QA13's forged-path test plants only `aws` and only in the copied harness (`services/platform/tests/integration/sprint28-s28r3-qa13-gate-fix.test.ts:80-105`). It does not attack `env` or `python3`.

**Required remediation:** invoke trusted absolute `env` and Python (or remove the helper dependency), validate them before any credential-bearing command construction, and add production-path adversarial tests for forged `env` and `python3` markers.

### CRITICAL-2 — The preferred AWS executable is replaceable through its unvalidated directory chain

The allowlist prioritizes `/opt/homebrew/bin/aws` (`scripts/lib/r2-ro-live.sh:17,95-99`), while validation checks only the final file's type, mode, and `root/self` owner (`:51-68`). It does not inspect every resolved parent directory. On the review host the resolver selected `/opt/homebrew/Cellar/awscli/2.35.18/libexec/bin/aws`; `/opt/homebrew/bin` and `/opt/homebrew/Cellar` are mode `0775`, owned by `inference1:admin`. This violates QA13's explicit non-group/world-writable trusted-chain requirement and lets a local group member replace the effective credential-bearing provider.

**Required remediation:** require a root-owned, non-writable resolved executable and validate every path component from the trusted root through the final file; apply the same rule to every curl fallback.

### CRITICAL-3 — Production fire-drill accepts arbitrary test/CLI execution with restore credentials

The committed consumer reads caller-controlled `HOLO_FIRE_DRILL_FAKE_VOLUMES` to skip real volume resolution (`scripts/run-fire-drill-on-fresh-target.sh:328-350,520`) and accepts caller-controlled `HOLO_CLI` (`:46,803-820`). The selected executable is launched under a child environment containing the restore access key, secret, and session token (`:767-820`). QA13's recorder test demonstrates this production-code path (`services/platform/tests/integration/sprint28-s28r3-qa13-gate-fix.test.ts:298-350`). This directly violates the requested absence of runtime provider/test overrides and can manufacture a fire-drill report.

**Required remediation:** move fake-volume/recorder/CLI substitution into an isolated copied harness. Production must use only its fixed CLI and real fresh-target volume resolution.

### HIGH-1 — Prefix scope can falsely pass for a broader credential

The outside-prefix check performs only `HeadObject` on the never-established `drill-neg-out-of-prefix/qa13-scope-probe.txt` (`scripts/prove-r2-readonly.sh:493-511`). A success fails, but `404`, `NoSuchKey`, and even unclassified nonzero results pass. A credential with broad `GetObject` access receives the same missing-object result, so this does not prove denied authorization. The fixture forces broad access to return success (`services/platform/tests/integration/fixtures/bin/aws:98-104`), masking the real ambiguity. There is no outside-prefix List or Get check.

**Required remediation:** use known-existing controlled out-of-prefix evidence and require explicit `AccessDenied` for List, Head, and Get; do not accept missing-object or arbitrary failure as scope proof.

### HIGH-2 — QA13 does not exercise every mutation through the actual fire-drill consumer

All six fire-drill mutation cases assert only nonzero status (`services/platform/tests/integration/sprint28-s28r3-qa13-gate-fix.test.ts:256-272`). Their copied harness lacks the normal CLI, so a run fails later for that reason. In an isolated mutant, removing `r2_ro_validate_proof` at `scripts/run-fire-drill-on-fresh-target.sh:264` still left QA13 green (24/24). The provision mutation mutant is correctly killed; the fire-drill matrix is not.

**Required remediation:** give each fire-drill mutation a success-capable harness baseline, assert the unmutated run reaches the recorder, require the mutated run to fail specifically at proof validation, and prove the recorder is not invoked.

### MEDIUM-1 — Exact endpoint-input rejection is incomplete

Although the endpoint used after context establishment is derived by `r2_ro_derive_endpoint` (`scripts/lib/r2-ro-live.sh:133-136`), a supplied endpoint is lowercased and stripped of one trailing slash before equality comparison (`:207-213`). For example, `https://<account>.r2.cloudflarestorage.com/` is accepted. QA13 requires rejection of supplied path/normalization ambiguity, not normalization before acceptance.

### MEDIUM-2 — No-follow and FD safety have a weak source-pattern oracle

The current code opens through a directory FD with `O_NOFOLLOW` and validates the returned file FD (`scripts/lib/r2-ro-live.sh:358-399`). But QA13 tests only for the strings `dir_fd`, `O_NOFOLLOW`, and `fstat` (`services/platform/tests/integration/sprint28-s28r3-qa13-gate-fix.test.ts:217-224`). An isolated mutation that removed the proof-file `O_NOFOLLOW` flag still passed focused QA13 (24/24). A replacement/symlink process test is required.

### MEDIUM-3 — Mint success/error and all-evidence canary checks are test theatre

The copied harness forwards AWS mock variables only (`scripts/test-harness/make-r2-ro-test-harness.sh:53-74`). Mint runs curl under `env -i` (`scripts/prove-r2-readonly.sh:197-201`), so QA13's `HOLO_CURL_*` mock/canary values (`sprint28-s28r3-qa13-gate-fix.test.ts:363-407`) never reach fixture curl; neither mint branch asserts a status. Separately, the recorder/parity test scans stdout, recorder output, and parity report (`:347-360`), but not proof JSON or attestation. A proof-payload canary mutation survived and appeared in generated proof evidence.

### MEDIUM-4 — Committed production proof mutator remains callable

`HOLO_QA_PROOF_MUTATE` remains in the committed helper (`scripts/lib/r2-ro-live.sh:436-465`) and both actual consumers invoke it (`scripts/provision-fresh-restore-target.sh:237-241`, `scripts/run-fire-drill-on-fresh-target.sh:260-264`). It is an explicit runtime test seam in production code, contrary to QA13's copied-harness-only requirement, even though the listed mutations fail closed.
