## Executive Summary

The PRD has a strong architectural direction and unusually good real-service test intent, but it is not yet safe to turn into implementation sprints. The highest-risk hole is the cutover promise: a writable post-flip soak cannot also roll back to a frozen Convex instance with zero data loss. The other blocking gaps are missing executable parity inventories, conflicting temporal-ledger rules, underspecified Zero/SSE write contracts, and incomplete ETL/blob/decommission recovery plans.

The recommended disposition is **needs revision before `/kb-sprint-plan`**. The changes below preserve the locked platform decisions; they make those decisions executable and testable.

## HIGH Confidence Findings (3 Planner Agents Agree)

- [ ] **G1 — The rollback guarantee contradicts a writable post-flip soak.** | Severity: **Critical**

  **Evidence:** `08-uc-sync.md:45-62` flips the app and MCP to Postgres and then promises a zero-loss rollback because Convex writes were frozen; `09-capability-chains.md:24-29` repeats that claim. New writes accepted by the flipped stack are absent from frozen Convex.

  **Suggested change:** Add a **Rollbackable-soak write policy** to UC-SYNC-03/04 and choose exactly one model: (a) read-only soak, (b) a tested, idempotent Postgres→Convex reconciliation/replay path, or (c) point-of-no-return at the first post-flip production write. Include scheduled jobs, MCP mutations, and mission commits. Replace the unconditional “zero committed-data loss” statement with the chosen guarantee.

  **New AC:** Perform representative app, MCP, and scheduled-job writes during the proposed soak and execute a rollback drill. Prove either the writes are blocked and visibly explained, or every committed write is preserved by the replay/reconciliation procedure.

  Agents: `mastra-planner`, `convex-planner`, `react-native-ui-planner`

- [ ] **G2 — Behavior-preserving parity has no complete, versioned source-of-truth mapping.** | Severity: **Critical**

  **Suggested change:** Add three machine-readable, reviewable companion artifacts before sprint planning:

  - `12-convex-source-catalog.md`: every legacy table/field/storage reference, disposition, transform, FK rewrite, expected-count formula, and owner.
  - `13-client-data-contract.md`: every Convex hook/action, consuming route, target Zero query or Hono command, ordering/pagination, optimistic/rejection behavior, and e2e case.
  - `14-mcp-compatibility-manifest.md`: every tool’s input/output/error contract, defaults, ordering, side effects, idempotency, transport support, and frozen-export fixtures.

  **New AC:** CI rejects an unmapped legacy surface; every catalog entry has an approved target/disposition; side-by-side golden tests prove the explicitly preserved behavior. Intentional contract changes require an approved, versioned exception.

  Agents: `mastra-planner`, `convex-planner`, `react-native-ui-planner`

## LOW Confidence Findings (One Planner Agent Identified; Evidence Is Direct)

- [ ] **G7 — Ledger immutability contradicts belief revision.** | Severity: **Critical**

  **Evidence:** UC-PLAT-01 rejects every `UPDATE`/`DELETE` on evidence tables (`04-uc-plat.md:22-28`), yet UC-DATA-02 requires stamping the preceding belief’s `tx_to` on revision (`05-uc-data.md:34-40`; `03-data-schema.md:30-32`). Stamping is an update.

  **Suggested change:** Add a single **Temporal write model**. Prefer denying direct DML while allowing one narrowly scoped, transactional DB function that verifies the expected current version, closes the predecessor, inserts the successor, and records actor/run/idempotency metadata. State exactly which tables/columns it may modify.

  **New AC:** Direct UPDATE/DELETE fails; authorized revision is atomic; concurrent revisions cannot produce two current beliefs; as-of queries remain correct.

  Agent: `mastra-planner`

- [ ] **G8 — Queue semantics promise impossible “exactly once” delivery from leases alone.** | Severity: **Critical**

  **Evidence:** `04-uc-plat.md:46-51` equates `SKIP LOCKED` leases and kill-9 retry with no duplicate side effect. A worker can perform an external effect and die before acknowledging it.

  **Suggested change:** Change the promise to **at-least-once execution with exactly-once observable effects**. Specify a transactional outbox/inbox, stable idempotency keys, consumer deduplication, fencing tokens, and either provider idempotency keys or compensating action for every external effect.

  **New AC:** Kill the worker before commit, after commit/before enqueue, and after dispatch/before acknowledgement; prove one observable result for each supported effect.

  Agent: `mastra-planner`

- [ ] **G9 — Zero’s required mutation/query protocol is absent, and write ownership is ambiguous.** | Severity: **High**

  **Evidence:** `04-api-design.md:25` says writes use `/api/*` “or” custom mutators; `07-ui-infrastructure.md:15-18` requires optimistic custom mutators but gives no server endpoint, mutation ID, conflict, or rejection contract. Zero’s official model requires client/server mutators and a push/mutate endpoint. [Zero mutators documentation](https://zero.rocicorp.dev/docs/mutators)

  **Suggested change:** Add the Zero query/mutate routes and a command classification matrix: simple client-visible CRUD uses Zero mutators; command-like operations (chat, mission start, uploads) use authoritative Hono commands. Define client-generated IDs, idempotency, optimistic rollback, validation error shape, conflict/version policy, and offline queueability per operation.

  **New AC:** Airplane-mode read, queued mutation/reconnect, server rejection after optimistic render, duplicate replay, and concurrent edit tests pass with a visible final state and no duplicate row/message.

  Agent: `react-native-ui-planner`

- [ ] **G10 — SSE reconnect is a requirement without a replay protocol.** | Severity: **High**

  **Evidence:** `06-uc-svc.md:46-52` promises reconnect survival, while `04-api-design.md:16` specifies only one POST stream. No cursor, event ID, sequence, persistence cadence, duplicate rule, or terminal-state reconciliation is defined.

  **Suggested change:** Define a chat-run protocol: immutable run ID and request idempotency key; event envelope with monotonic sequence; persisted delta/final/error model; a resume endpoint or `Last-Event-ID` rule; and the authoritative rule for reconciling SSE deltas with the Zero-synced durable message.

  **New AC:** Disconnect before and after persisted deltas, resume from cursor, inject duplicate/out-of-order events, and assert final durable text appears exactly once.

  Agent: `react-native-ui-planner`

- [ ] **G11 — ETL reconciliation cannot use a literal 1:1 row-count assertion after declared drops and merges.** | Severity: **Critical**

  **Evidence:** `03-data-schema.md:15-24` merges research/analysis and drops `documentCounters`/`rateLimits`; UC-DATA-05 says every target count equals its source count (`05-uc-data.md:71-73`).

  **Suggested change:** Replace that AC with a disposition-aware reconciliation matrix: source count, target formula, exclusions and reasons, checksum/sample requirements, and approval for each intentional loss/merge.

  **New AC:** A machine-readable report has zero unexplained variance across all 60 source tables and all legacy storage references.

  Agent: `convex-planner`

- [ ] **G12 — “Freeze Convex writes” is not an executable cutover gate.** | Severity: **High**

  **Evidence:** `08-uc-sync.md:43-50` and `09-capability-chains.md:13-19` assume a freeze, but define no write fence, cron disablement, scheduled-work drain, quiet period, or export watermark. The migration itself identifies 16 crons (`04-uc-plat.md:46-51`).

  **Suggested change:** Add a cutover runbook with a durable write fence checked by every legacy mutation/action, cron/external-ingress disablement, scheduled-work cancellation/drain, export watermark, last-write audit, and abort procedure.

  **New AC:** Before export: no runnable scheduled jobs, zero successful writes for a declared quiet interval, and a signed/logged freeze report containing final write timestamp and per-surface counts.

  Agent: `convex-planner`

- [ ] **G13 — There is no recoverability proof before deleting the final legacy source of truth.** | Severity: **High**

  **New AC:** Sprint 0 boots the exact stack on real Bun, executes agent/tool/workflow/MCP/OTel smoke paths, rejects unknown stage or role versions before run creation, resumes a pinned old run correctly, and fails closed when a required fleet capability is missing.

## Recommendations by Category

3. **Runtime correctness:** Resolve G7, G8, G14, and G15 before choosing task boundaries. They determine the actual data model, mission engine shape, and failure semantics.
4. **Client correctness:** Add the Zero and SSE contracts in G9/G10 and the selected e2e environment in G5 before assigning the RN rewrite.
5. **Operational policy:** Reconcile access control (G16) and document protocol/count dates (G17) so acceptance gates have a stable basis.
