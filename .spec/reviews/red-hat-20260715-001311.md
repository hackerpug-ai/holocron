## MEDIUM Confidence Findings (2 Agents Agree)

- [ ] **M-1: No FK constraints — referential integrity unenforced at DB level** | Severity: Medium
      Agents: mastra-reviewer, convex-reviewer
      All inter-table references are `text` columns (e.g., `conversation_id text`, `source_id text`) with indexes but zero `FOREIGN KEY` / `REFERENCES` clauses. This is a deliberate migration-flexibility choice (loose coupling with legacy Convex IDs), but means orphan rows can accumulate during ETL with no DB-level protection. FKs may be desired post-migration (Sprint 14+).

- [ ] **M-2: `documents.embedding` catalog disposition contradicts schema** | Severity: Medium
      Agents: convex-reviewer (primary), mastra-reviewer (corroborating — confirms vectors correctly on passages)
      The source catalog (`12-convex-source-catalog.yaml`) declares `documents.embedding: preserve → documents.embedding`, but the Drizzle schema intentionally omits this column (vectors live on `passages` per the Zero split architecture). The catalog was authored in Sprint 02 before the architectural decision and hasn't been amended. When Sprint 05+ runs the ETL, Convex document embeddings would have no landing column. **Fix:** update the catalog disposition to `regenerate` (re-embed into passages) before Sprint 14 ETL. This is a catalog amendment, not a schema defect — the schema correctly implements AP-1/CAP-SYNC-01.
