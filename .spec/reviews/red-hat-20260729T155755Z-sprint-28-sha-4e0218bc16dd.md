### HIGH-1 — Caller can replace the mandatory real R2 proof executable

**Confidence:** High  
**Prior finding remediated?:** No — this is an equivalent caller-controlled proof authority to the closed proof-file bypass.

Both consumers choose `HOLO_PROVE_R2_READONLY` over the repository prover and execute it with Bash:

- `scripts/provision-fresh-restore-target.sh:192-210`
- `scripts/run-fire-drill-on-fresh-target.sh:211-229`

There is no test-only gate, path/owner allowlist, digest verification, or producer verification. A caller can point the variable at a script that writes valid-shaped JSON with a matching tuple fingerprint, then succeeds without calling the real R2 List/Put/Delete denial probe. QA10 itself demonstrates this replacement mechanism by passing `qa10-prove-stub.sh` at `sprint28-s28r3-qa10-gate-fix.test.ts:91,198`; that fixture emits simulated successes at `fixtures/qa10-prove-stub.sh:50-54` and writes the accepted fields at `:55-84`.

This violates QA10 MUST 1 and NEVER clauses: live mode must run `prove-r2-readonly.sh`, and caller-controlled proof material must not be authority.

**Required remediation:** remove the environment executable override from live consumers. If test injection is required, put it behind a compile/test-only guard that cannot activate in `REQUIRE_LIVE_R2_RO=1`, or invoke a fixed, repository-owned immutable path with an explicit test seam outside the live path.

### HIGH-2 — Live R2/Cloudflare output and credential-shaped API error fields remain loggable

**Confidence:** High  
**Prior finding remediated?:** Partial only; mint JSON parse exceptions are sanitized, but the complete logging requirement is not met.

`prove-r2-readonly.sh` captures remote/AWS output with `2>&1` and republishes it as `detail`, `ls sample`, or `stderr`:

- capture points: `:398`, `:414`, `:449`, `:466`;
- output points: `:403`, `:408`, `:429`, `:435`, `:457`, `:476`, `:481`.

Those branches print up to 400 bytes of service-controlled content without a redactor. The mint parser also turns string elements of `errors` into `err_class` and prints the result at `:221-232`; this is not a fixed error-code class. The implementation review's fake responses demonstrated both a credential canary emitted through `API_FAIL` and arbitrary AWS output emitted via `detail:`.

QA10 checks only source text for the mint parser (`sprint28-s28r3-qa10-gate-fix.test.ts:323-330`), never executes its error paths, and never covers the AWS branches.

**Required remediation:** log only fixed operation names, exit/status classes, and numeric/provider-controlled error codes after strict numeric validation. Remove all raw `ls_out`, `put_out`, `del_out`, and `api_out` interpolation, including success samples. Add subprocess tests with canaries in fake mint and AWS responses; assert absence from stdout, stderr, and every evidence file.

### MEDIUM-1 — Attestation does not bind the effective endpoint, bucket, prefix, or policy

**Confidence:** High  
**Contract:** QA10 MUST 2.

The evidence payload stores only `endpoint_present`, `bucket_present`, and `prefix_present` booleans and no policy value or fingerprint (`scripts/prove-r2-readonly.sh:615-625`). Consumer validation verifies only the tuple fingerprint, permission booleans, and timestamp (`scripts/provision-fresh-restore-target.sh:234-254`; `scripts/run-fire-drill-on-fresh-target.sh:241-254`). Provision builds the policy after consuming the proof (`scripts/provision-fresh-restore-target.sh:299-318`). This falls short of the required full effective tuple **plus endpoint/bucket/prefix/policy context** binding.

**Required remediation:** canonicalize the effective endpoint, bucket, prefix, and policy; include a non-secret context digest in the proof; verify that digest immediately before each consumer uses the tuple.

### MEDIUM-2 — Caller-selected proof path is not a private-file-safe evidence boundary

**Confidence:** High  
**Contract:** QA10 MUST 2.

The consumers follow and truncate `HOLO_R2_RO_PROOF_PATH` and ignore a failed `chmod 600` (`scripts/provision-fresh-restore-target.sh:182-191`; `scripts/run-fire-drill-on-fresh-target.sh:203-210`). Their post-check rejects only world-writable files, not any non-0600 mode (`provision:225-228`; `runner:238-240`). A symlink/caller-selected path therefore is not the promised private mode-0600 evidence file and introduces avoidable path-target hazards.

**Required remediation:** create the evidence file with an exclusive, no-follow operation in a trusted directory, require mode exactly 0600, and do not expose a production caller-selected output path.
