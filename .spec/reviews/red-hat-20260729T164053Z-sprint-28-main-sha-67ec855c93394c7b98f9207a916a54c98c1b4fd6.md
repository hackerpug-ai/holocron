## Findings

### CRITICAL-1 — Caller can choose the committed fake AWS implementation as the “trusted” live provider

**Confidence:** High

`r2_ro_verify_provider_bin` accepts any executable below `services/platform/tests/integration/fixtures` ([r2-ro-live.sh](/Users/inference1/Projects/holocron/scripts/lib/r2-ro-live.sh:52)), and `r2_ro_resolve_trusted_aws_bin` treats a caller-provided `HOLO_TRUSTED_AWS_BIN` in that directory as trusted ([r2-ro-live.sh](/Users/inference1/Projects/holocron/scripts/lib/r2-ro-live.sh:83)). There is no test-only guard and both actual consumers pass that caller value to the prover ([provision-fresh-restore-target.sh](/Users/inference1/Projects/holocron/scripts/provision-fresh-restore-target.sh:212), [run-fire-drill-on-fresh-target.sh](/Users/inference1/Projects/holocron/scripts/run-fire-drill-on-fresh-target.sh:235)).

Independent process proof: with only safe invented credentials and `HOLO_TRUSTED_AWS_BIN=services/platform/tests/integration/fixtures/bin/aws`, `provision-fresh-restore-target.sh --dry-run --skip-isolation` exited 0 and reported a live List/Head/Put-denied/Delete-denied proof. That fixture is a synthetic success/denial implementation, not Cloudflare R2. Thus the old bare-`PATH` exploit is closed, but a caller can still forge a live success through a committed fake provider.

**Required remediation:** never permit a test fixture provider in production/live mode. Use a fixed system allowlist (or pinned repository provider) only; make fixtures conditional on an explicit non-production test harness guard that live consumers refuse.

### CRITICAL-2 — Cloudflare mint still executes caller-selected `curl` from `PATH`

**Confidence:** High

The `--try-mint` provider path checks `command -v curl` then invokes bare `curl` ([prove-r2-readonly.sh](/Users/inference1/Projects/holocron/scripts/prove-r2-readonly.sh:173), [prove-r2-readonly.sh](/Users/inference1/Projects/holocron/scripts/prove-r2-readonly.sh:198)). It sends the Cloudflare bearer token and JSON containing the parent access-key ID to that process. QA test setup intentionally prepends a fake `curl` directory to `PATH` ([sprint28-s28r3-qa9-gate-fix.test.ts](/Users/inference1/Projects/holocron/services/platform/tests/integration/sprint28-s28r3-qa9-gate-fix.test.ts:65)); no runtime validation pins this implementation.

This contradicts the QA12 trusted-provider/runtime requirement and exposes the Cloudflare credential-mint boundary to a caller `PATH` replacement, even though AWS itself is now run with a restricted `PATH`.

**Required remediation:** resolve and validate a trusted absolute `curl` (or replace the subprocess with a pinned provider); execute it under an allowlisted `env -i`; reject caller overrides and fixture paths outside an explicitly isolated test mode.

### HIGH-1 — “Canonical context” remains self-attested and cannot prove the effective read scope

**Confidence:** High

`r2_ro_canonical_endpoint` only lowercases and removes one trailing slash; the subsequent validation accepts any nonempty `https://` value ([r2-ro-live.sh](/Users/inference1/Projects/holocron/scripts/lib/r2-ro-live.sh:107), [r2-ro-live.sh](/Users/inference1/Projects/holocron/scripts/lib/r2-ro-live.sh:195)). The policy JSON is generated from caller bucket/prefix strings and an optional supplied policy is compared only to that regenerated string ([r2-ro-live.sh](/Users/inference1/Projects/holocron/scripts/lib/r2-ro-live.sh:212)).

The List/Head/Put/Delete probes prove positive access under the declared prefix and lack of two write actions at a sacrificial key; they do not establish that the credential lacks reads outside that prefix, nor bind the endpoint to the intended R2 account. QA12 has no broader-read/different-prefix process fixture despite its stated contract.

**Required remediation:** derive/account-bind endpoint from trusted configuration, and obtain or validate authoritative effective policy/scope sufficient to reject broader object reads. Add real-consumer broader-scope and endpoint-substitution negatives.

### MEDIUM-1 — Proof consumption is still a TOCTOU follow race

**Confidence:** High

The writer is substantially corrected: exclusive creation, no-follow, mode `0600`, and the verified `0700` directory are present. But the reader checks `lstat()` and then calls Python `open(path, "r")`; unlike creation, that open has no `O_NOFOLLOW` and uses no directory FD ([r2-ro-live.sh](/Users/inference1/Projects/holocron/scripts/lib/r2-ro-live.sh:358)). **Required remediation:** open via directory FD plus `O_NOFOLLOW`, validate the returned FD with `fstat`, and parse only that FD.
