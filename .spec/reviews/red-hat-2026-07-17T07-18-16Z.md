## MEDIUM Confidence Findings (both reviewers raised OR one reviewer with concrete evidence + behavioral impact)

- [ ] **M1 — Gate step 3 cannot independently prove repair from its log alone** | Severity: **MEDIUM**
      Location: `services/platform/src/cli/holo.ts:1816-1817` (success-path CLI output omits `attempts`); gate step 3 evidence log
      Agents: `code-reviewer` (G7, primary), `mastra-reviewer` ("gate-evidence completeness gap") — **independent agreement**
      Evidence: `holo.ts` success output emits `{ok, extractionId, result, schema, role}` — **no `attempts` field**. Step 3's log therefore shows `ok:true` + valid object but cannot distinguish "model returned valid JSON on attempt 1" from "repair loop entered and succeeded on attempt 2." The behavioral test `struct-repair-loop.test.ts:172-178` PROVES repair entry (`expect(status?.attempts).toBeGreaterThanOrEqual(2)`), but that's a separate code path from the gate. C2-H3 added `attempts` to the status record — the gate step just doesn't surface it.
      Expected: either include `attempts` in the CLI success JSON, or extend gate step 3 to also run `holo extract:status <extractionId>` and assert `status.attempts >= 2`.
      Risk if unfixed: a future regression where the repair loop silently short-circuits to first-try success would not be caught by the human gate (the test suite would, but the gate is supposed to be the operator's independent proof).

- [ ] **M2 — `findTripwireMatches` under-reports multi-kind sensitive content** | Severity: **MEDIUM**
      Location: `services/platform/src/inference/extract-structured.ts:284-297`
      Agents: `code-reviewer` (G1, primary), `mastra-reviewer` (5b) — **independent agreement**
      Evidence: the for-loop returns on the first match (`:293`), so `redactedTripwirePayload` always reports `patterns: [hit.kind]` — a single-element array. If input or model output contains both an SSN and an API key, only the first matching kind is reported. The extraction IS correctly blocked (safety invariant holds), but operator visibility is reduced: an audit trail would miss co-occurring sensitive types.
      Expected: collect all matching kinds before returning; report the union in `redactedTripwirePayload.patterns`.

- [ ] **M3 — `writeExtractionStatus` swallows persistence errors silently** | Severity: **MEDIUM**
      Location: `services/platform/src/inference/extract-structured.ts:140-152` (notably `:148` — empty `catch {}`)
      Agents: `code-reviewer` (G2, primary), `mastra-reviewer` (5g) — **independent agreement**

The comment says "best-effort" — deliberate design — but even a `console.warn` / stderr note would make silent degradation observable without changing the best-effort contract.
      Expected: log persistence failures at debug/warn level; do not re-throw (preserve best-effort).

- [ ] **M4 — `probeJsonSchemaSupport` over-broad catch (carried from prior M1)** | Severity: **MEDIUM**

Risk emerges if a json_schema-capable model is added and a programming bug masks its capability.
      Expected: narrow to expected errors (`AI_NoObjectGeneratedError`, network/timeout); rethrow unexpected errors.
