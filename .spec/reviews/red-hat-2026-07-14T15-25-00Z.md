## MEDIUM Confidence Findings (2 Agents Agree)

### M1. `evalFormula` identity default makes known-table variance a tautology
**Severity**: MEDIUM | **Agents**: convex-reviewer, mastra-reviewer
**Location**: `services/platform/src/catalog/reconcile.ts:38-48`
**Evidence**: For all 58 non-drop tables, `formula=count(source)` → `evalFormula` returns `sourceCount` → `variance = sourceCount - sourceCount = 0` always. The variance≠0 path (`reconcile.ts:106-111`) can never fire for a `count(source)` table. Only the orphan/unmapped export table path (lines 131-153) detects variance.
**Impact**: A formula/catalog mismatch on a known table (e.g., wrong formula string) would not be caught. This is a Phase-0 design choice — `count(source)` is correct for identity-migration preserve/merge tables — but the formula evaluation is permissive.
**Fix**: Fail on unrecognized formula strings (currently defaults to identity at line 47).

### M2. `assets.ts` hardcodes `ok: true`
**Severity**: MEDIUM | **Agents**: mastra-reviewer
**Location**: `services/platform/src/catalog/assets.ts:135`
**Evidence**: `ok: true` is unconditional. `holo.ts:175` exits 0 if `inv.ok`. A missing blob (`if (!blob) continue` at line 92) is silently omitted.
**Impact**: `catalog:assets` cannot fail on incomplete inventory. No AC explicitly requires this to fail, but Sprint 14's ETL will need a stronger guarantee.
**Fix**: Set `ok` based on whether all expected retained refs produced blobs.

### M3. `catalog:verify` without `--export` passes self-referentially
**Severity**: MEDIUM | **Agents**: mastra-reviewer
**Location**: `services/platform/src/cli/holo.ts:104`, `services/platform/src/catalog/verify.ts:170`
**Evidence**: When no `--export` is provided, `exp=null`. The export cross-check block is skipped. The gate passes on catalog self-consistency alone.
**Impact**: Latent — all integration tests and the human gate always pass `--export`. But CRITICAL CONSTRAINT says "MUST cross-check the catalog against the REAL export's actual surface."
**Fix**: Require `--export` for `catalog:verify` (like reconcile/assets do), or document catalog-only mode as intentionally weaker.

### M4. Verify cross-check is unidirectional (export→catalog only)
**Severity**: MEDIUM | **Agents**: mastra-reviewer
**Location**: `services/platform/src/catalog/verify.ts:170-182`
**Evidence**: Iterates `Object.keys(exp.tables)` checking `!catalogSet.has(tname)`. Does NOT iterate `Object.keys(catalog.tables)` checking absence from export. A catalog table absent from the export passes silently.
**Impact**: A stale/fictional catalog entry would not be caught. The 60-count gate partially compensates.
**Fix**: Add reverse-direction check.

### M5. No TDD RED commit provenance
**Severity**: MEDIUM | **Agents**: mastra-reviewer
**Location**: git history `8c1c84b..912fee1` — single 220-file commit
**Evidence**: Tasks catalog-2/3/5 declare `TDD_MODE: red_first`, `RED_GREEN_REQUIRED: yes`, "Gate 8: watched RED." No RED artifact or commit exists in git history. All code landed in a single commit.
**Impact**: Cannot verify RED-first from commit provenance. The negative controls ARE structurally correct (concrete failure signatures), but TDD process evidence is absent.
**Fix**: Accept as process debt or document retroactively.
