## Findings

### C1 — QA9 security tests are not mutation-resistant

**Severity:** CRITICAL  
**Confidence:** High — six disposable-worktree mutations left the focused suite green.

The passing QA8/QA9 suite does not prove the controls it claims to protect. The test-reality review made these isolated mutations and the focused suite still passed:

- bypassing the provision unknown-writer-secret rejection;
- making verifier file data overwrite an explicit environment token;
- removing provision stale/future proof rejection;
- removing fire-drill child session-token forwarding;
- making the sacrificial-key safety predicate always succeed; and
- adding a raw minted Access Key ID to the mint success log.

The principal weak oracles are [the generic unknown-writer failure match](../../services/platform/tests/integration/sprint28-s28r3-qa9-gate-fix.test.ts#L101), the token test that deliberately clears the environment and therefore never tests precedence ([lines 183–192](../../services/platform/tests/integration/sprint28-s28r3-qa9-gate-fix.test.ts#L183)), missing stale/future proof cases ([lines 212–279](../../services/platform/tests/integration/sprint28-s28r3-qa9-gate-fix.test.ts#L212)), and the recorder test that permits a pre-child volume failure and never reads `recorderOut` ([lines 312–348](../../services/platform/tests/integration/sprint28-s28r3-qa9-gate-fix.test.ts#L312)). The log test is source-pattern-only ([lines 378–383](../../services/platform/tests/integration/sprint28-s28r3-qa9-gate-fix.test.ts#L378)).

This leaves every QA9 security assertion vulnerable to a green-but-broken test result, including the required process-level token propagation and sacrificial-key safety checks.

**Required remediation:** use a deterministic fake Docker/volume path so the recorder must run; assert its redacted token metadata and absence of raw values. Add process-level negative cases for all four scripts, explicit environment-over-file conflicts, missing/equal/unknown writer shapes, malformed/mismatched/stale/future attestation fields, proof auto-run, the full denylist plus generated sacrificial key, and canary-based stdout/stderr/evidence leakage checks.

### H1 — Caller-controlled proof attestation bypasses the live RO permission oracle

**Severity:** HIGH  
**Confidence:** High — source trace and passing forged-attestation test.

When `HOLO_R2_RO_PROOF_PATH` points to an existing file, provision skips the in-process proof at [provision-fresh-restore-target.sh:179](../../scripts/provision-fresh-restore-target.sh#L179) and fire drill does the same at [run-fire-drill-on-fresh-target.sh:197](../../scripts/run-fire-drill-on-fresh-target.sh#L197). Both consumers then accept caller-controlled JSON booleans, a timestamp, and a 16-hex-character tuple-hash prefix ([provision:204–235](../../scripts/provision-fresh-restore-target.sh#L204); [runner:221–239](../../scripts/run-fire-drill-on-fresh-target.sh#L221)). The attestation has no signature, trusted writer, secure ownership check, or binding to endpoint/bucket/prefix/policy.

QA9 encodes the bypass as success: `writeProof()` creates an all-true synthetic attestation ([test:41–60](../../services/platform/tests/integration/sprint28-s28r3-qa9-gate-fix.test.ts#L41)) and the matching-proof provision test expects exit zero ([test:251–276](../../services/platform/tests/integration/sprint28-s28r3-qa9-gate-fix.test.ts#L251)). A caller that knows the restore credentials can compute the same fingerprint and claim that List/Put/Delete were tested without any live probe. This does not establish the required proof immediately before the exact tuple is consumed.

**Required remediation:** in live mode, always rerun `prove-r2-readonly.sh` immediately before provision/fire-drill consumption and write a fresh private temporary attestation. If reuse is required, authenticate a full-context binding (tuple, endpoint, bucket, prefix/policy, producer, time) with a trust boundary that the caller cannot forge; do not treat arbitrary `HOLO_R2_RO_PROOF_PATH` JSON as a proof.

### M1 — Fire-drill canonical token resolution can substitute the writer token

**Severity:** MEDIUM  
**Confidence:** High — deterministic source trace.

The runner reads `R2_RESTORE_SESSION_TOKEN` into `file_restore_st` ([run-fire-drill-on-fresh-target.sh:140–145](../../scripts/run-fire-drill-on-fresh-target.sh#L140)), but also exports canonical-file `R2_SESSION_TOKEN` as generic configuration. It then selects that generic token before `file_restore_st` ([lines 170–175](../../scripts/run-fire-drill-on-fresh-target.sh#L170)). Therefore a normal secrets file containing both the writer `R2_SESSION_TOKEN` and the restore `R2_RESTORE_SESSION_TOKEN` binds/provides the writer token to the supposedly restore-only tuple and child.

This typically fails closed at the external credential endpoint, but it violates the canonical restore-token contract and the exact-tuple proof binding. QA9 tests only the verifier's file-load path, not runner precedence.

**Required remediation:** keep generic writer session state separate; resolve `RESTORE_ST` as explicit `R2_RESTORE_SESSION_TOKEN` environment value first, then `file_restore_st`, and only use generic `R2_SESSION_TOKEN` under an explicitly documented fallback that cannot be populated from canonical writer data. Add a process fixture containing distinct generic and restore tokens and assert the child gets only restore-token metadata.

### L1 — Mint error output is not credential-redacted

**Severity:** LOW  
**Confidence:** Medium — source-path evidence; no live API response was used.

The normal mint success line no longer prints an Access Key ID fragment ([prove-r2-readonly.sh:243–250](../../scripts/prove-r2-readonly.sh#L243)). However, on a Cloudflare API error the script emits the entire `errors`/`messages` object, or the first 200 bytes of the raw response ([lines 215–218](../../scripts/prove-r2-readonly.sh#L215)). That is unredacted remote error content and conflicts with the strict zero credential-value logging requirement if an upstream/proxy response reflects credentials or request data.

**Required remediation:** log only HTTP status and a fixed error class/code; never print raw response content or arbitrary API message structures. Cover the path with canary values in a mocked response.
