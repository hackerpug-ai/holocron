# MK6-RUNTIME-001: Make runtime readiness release-bound and truthful

> Assignee: mastra-implementer

> Priority: P0
> Type: bugfix
> Wave: 4

> Depends on: MK6-HOST-001, MK6-FLEET-001, MK6-DATA-001, MK6-QUEUE-001, MK6-BACKUP-001

## Outcome

The already-listening external Bun/Mastra process at private `:44111/health` returns 200 only when independently observed release, Postgres, fleet, scheduler, backup, and alert identities are current.

## Acceptance Criteria

- [ ] AC-1: `PLATFORM_IT=1 bash scripts/verify-mk6-runtime-health.sh --base-url "$MK6_PRIVATE_BASE_URL" --consecutive 3 --json` queries the already-listening process externally and observes three 200s with one source SHA/image/generation/host, a non-empty Postgres database identity, one real fleet completion identity, bounded queue sessions, and independently queried fresh scheduler/backup/alert ages.
- [ ] AC-2: An isolated candidate wired to the wrong fleet returns `503 FLEET_IDENTITY_MISMATCH` at the same external endpoint.
- [ ] AC-3: An isolated candidate wired to the wrong database returns `503 DATABASE_IDENTITY_MISMATCH`.
- [ ] AC-4: An isolated candidate with its release identity omitted returns `503 RELEASE_IDENTITY_MISSING`.
- [ ] AC-5: An isolated candidate with an overdue scheduler heartbeat returns `503 SCHEDULER_HEARTBEAT_OVERDUE`.
- [ ] AC-6: An isolated candidate with overdue backup/alert heartbeats returns `503 BACKUP_HEARTBEAT_OVERDUE`.

## Test Criteria
